# EchoRoom 设计文档（实时语音聊天室）

> 日期：2026-09-16 ｜ 状态：待用户审阅 ｜ 定位：个人学习项目

## 1. 项目概述

**EchoRoom** 是一个类似 Oopz 的实时语音聊天室：一个固定房间，打开客户端即自动连接，房间内成员可以**实时语音交谈**（最多 6 人、允许同时说话），并带有**公屏文字消息**。

- **目标定位**：个人学习与技术研究项目（简历/能力导向）。核心链路（网络收发与转发、音频采集播放、抖动缓冲、混音）全部亲手实现；仅"无学习意义"的部分使用成熟库（如 Opus 编解码器）。
- **技术基调**：延续 LetterSink 的路线——Rust、std 线程 + channel、WASAPI、tauri WebView 做界面，不使用 async 框架。
- **复用经验**：LetterSink 的 WASAPI 采集经验（麦克风采集与回环采集同款 API）、tauri 的 invoke/emit 桥接模式、分层独立验证工具策略。

## 2. 需求与约束

| 维度 | 结论 |
|------|------|
| 房间 | **单房间**（服务器即房间），打开客户端自动连接 |
| 规模 | **最多 6 人**，允许 2~3 人同时说话 |
| 部署 | 公网：阿里云 ECS 经济型 e（**2 核 2G + 3M 带宽**）；开发期先本机/局域网 |
| 客户端平台 | Windows 桌面（tauri 应用） |
| 音频设备 | **戴耳机假设**——不做回声消除（AEC），设计上留为扩展点 |
| 功能 | 实时语音 + 公屏文字 + 成员列表（说话状态高亮） |
| 带宽核算 | 6 人转发峰值约 1.2 Mbps（3M 带宽的 40%，余量充足）；不适合视频/屏幕共享 |

## 3. 总体架构

```
┌─ 成员电脑（客户端：tauri 应用）────────────────────┐
│  UI（WebView/HTML）：成员格、公屏、输入框、连接状态  │
│        ↕ invoke / emit（与 LetterSink 同款桥接）    │
│  Rust 后端：                                       │
│    采集线程 → Opus 编码 → UDP 发 ─────────────┐    │
│    UDP 收 → 抖动缓冲 → 解码 → 混音 → 播放 ────┤    │
│    TCP 控制线程（登录/公屏/说话状态）─────────┐│    │
└─────────────────────────────────────────────┼┼────┘
                                              ││
┌─ 阿里云 ECS（服务端：无界面 Rust 程序）───────┴┴────┐
│  TCP：每连接一线程（登录、成员管理、公屏、状态广播）  │
│  UDP：单 socket 主循环——语音包原样转发给其他成员    │
│       （不解码、不混音、不加工）                    │
└────────────────────────────────────────────────────┘
```

**核心设计决策**：

1. **服务器只做"管道"**：UDP 收包 → 按来源地址映射到成员 → 原样转发给房间内其他成员。CPU 开销趋近于零，延迟最低、音质无损。所有音频理解（解码、混音）都在客户端——学习点集中的地方。
2. **双通道各司其职**：TCP 承载控制（有序可靠：登录/成员列表/公屏/说话状态）；UDP 承载语音（快：丢几帧 Opus 天然可容忍）。互不影响。
3. **客户端四条线程 + channel**（std 线程，不用 async）：

| 线程 | 职责 |
|------|------|
| 采集线程 | 麦克风 → 20ms 一块 → Opus 编码 → UDP 发出；同时做音量检测（说话状态判定） |
| 接收线程 | UDP 收各成员语音包 → 按来源放入各自抖动缓冲 |
| 播放线程 | 声卡事件驱动：取各缓冲帧 → 解码 → 软混音 → 写 WASAPI 播放 |
| TCP 线程 | 控制消息收发；说话状态翻转时上报 |

4. **身份与 UDP 绑定**：TCP 登录分配 `uid + 随机 token`；客户端 UDP 首包 `Register{uid, token}` → 服务器记录 `地址 ↔ 成员` 映射。

## 4. 协议设计（自研二进制协议）

### 4.1 报文格式

**TCP（控制通道）**——字节流必须分帧：

```
[长度 u32][类型 u8][载荷...]
载荷：手写二进制序列化（字符串 = 长度 u16 + UTF-8 字节）
```

**UDP（语音通道）**——固定头 + 小载荷：

```
[u16 魔数][u8 版本][u8 类型][u16 来源 uid][u32 序列号][载荷: Opus 帧]
```

### 4.2 消息清单

| 通道 | 方向 | 消息 | 说明 |
|------|------|------|------|
| TCP | C→S | `Login{昵称}` | 进入房间 |
| TCP | S→C | `LoginOk{uid, token, 成员列表}` | 含自己与已有成员 |
| TCP | S→C | `MemberJoin{uid, 昵称}` / `MemberLeave{uid}` | 成员变化广播 |
| TCP | C→S | `Chat{文本}` | 公屏文字 |
| TCP | S→C | `Chat{uid, 文本}` | 公屏广播 |
| TCP | C→S | `Speaking{bool}` | 说话状态翻转时上报 |
| TCP | S→C | `Speaking{uid, bool}` | 说话状态广播（蓝框） |
| UDP | C→S | `Register{uid, token}` | 绑定地址映射 |
| UDP | S→C | `RegisterAck` | 绑定确认 |
| UDP | C→S | `Voice{seq, opus}` | 语音帧（说话时） |
| UDP | C→S | `Heartbeat{seq}` | 心跳（每 2s；说话时语音包即心跳） |
| UDP | S→C | `Voice{来源 uid, seq, opus}` | 转发时补上来源 uid |

### 4.3 心跳与地址映射生命周期

```
客户端：每 2 秒发 UDP 心跳（兼 NAT 保活——家用路由器 UDP 映射约 30s~2min 超时）
服务器：成员记录 last_seen；收到任何包（语音/心跳）刷新
        超时 15 秒 → 清除该地址映射（音频通道失效）
客户端：一段时间收不到任何音频/心跳响应 → 自动重发 Register（网络切换自愈，新 IP 自然生效）
```

**两层状态（服务器端）**：
- **在线成员**：以 TCP 连接为准（断开 = 离开，广播 MemberLeave）
- **音频可达**：以 UDP 映射为准（超时仅清地址，成员仍在列表，重注册恢复）

### 4.4 安全边界（明示取舍）

- Token 校验防止冒名发语音；畸形包一律丢弃 + 计数日志
- **不加密**（公网明文传输）——朋友房间、学习项目接受的取舍；未来升级点：DTLS/TLS
- 服务器**不无检查地信任 uid**：语音包按"来源地址"反查成员，注册后地址与 uid 绑定

## 5. 客户端设计

### 5.1 目录结构

```
EchoRoom/
├── protocol/        共享协议 crate（报文编解码；客户端/服务端共同依赖，单一事实来源）
├── server/          服务端（无界面 Rust 程序）
└── client/          客户端（tauri 应用）
    ├── src-tauri/   Rust：音频 + 网络 + 桥接
    │   ├── audio/   采集、编码、解码、抖动缓冲、混音、播放
    │   ├── net/     TCP 控制 + UDP 语音
    │   └── bridge.rs  tauri 命令与事件
    └── ui/          前端 HTML/JS/CSS（纯静态）
```

### 5.2 音频链路参数

| 环节 | 设计 |
|------|------|
| 采集 | WASAPI 麦克风，**48kHz 单声道** |
| 帧 | **20ms = 960 样本** → Opus 一帧 |
| 编码 | Opus，**32~48 kbps** |
| 采样率 | 统一 48kHz——**无需重采样**（Opus 原生 48k） |
| 说话检测 | 每帧能量 → 平滑 → **双阈值迟滞**（进入/退出阈值分离，防蓝框闪烁）→ 翻转才上报 |
| 抖动缓冲 | **每发送者一条**独立缓冲：按序列号排序、目标保持 **3~4 帧（60~80ms）水位**、缺帧短等后跳过（触发 Opus 丢包隐藏 PLC） |
| 混音 | 每播放周期：各成员当前帧**分别解码得 PCM** → **逐样本相加 → 软限幅**（防爆音） |
| 播放 | WASAPI 扬声器，**事件驱动**（声卡每次要数据 → 取混音结果写出；整链路由声卡时钟驱动，不漂移） |

### 5.3 UI 结构与入口行为

```
┌─────────────────────────────────────┐
│ EchoRoom          [连接状态: 已连接]   │
├─────────────────────────────────────┤
│  成员网格（一行 3 个，超出滚动）        │
│  说话中 → 蓝色描边高亮                 │
├─────────────────────────────────────┤
│  公屏（消息滚动区，自动滚到底）         │
├─────────────────────────────────────┤
│  [输入框................] [发送]      │
└─────────────────────────────────────┘
```

- 首次启动：输入昵称 + 服务器地址 → 存入本地配置
- 之后启动：自动 TCP 登录 → UDP 注册 → 直接进房间
- 顶栏连接状态：`已连接 / 重连中…`

### 5.4 客户端容错

- TCP 断开 → 自动重连，退避 1s → 2s → 5s → 10s，UI 显示"重连中"
- UDP 长时间无响应 → 自动重新 Register
- 麦克风/扬声器缺失或被占用 → UI 明确报错，不崩溃
- 单个语音帧解码失败 → 丢弃该帧，链路继续

## 6. 服务端设计

### 6.1 线程与状态模型

```
主线程：TCP accept 循环 → 每连接 spawn 连接线程
    读线程：解析控制消息 → 改房间状态 → 触发广播
    写线程：从发送队列（mpsc）取消息 → 写出（慢客户端只堵自己）
UDP 线程：单 socket 主循环——收包 → 查源地址对应成员 → 转发
清理线程：每 5s 扫描 → last_seen 超 15s → 清 UDP 映射
共享状态：Arc<Mutex<RoomState>>{ uid → 昵称、TCP 发送队列、UDP 地址、last_seen }
```

### 6.2 关键流程

**登录 + 音频注册**：
```
C ──TCP── Login{昵称}
S    分配 uid + 随机 token；检查容量（满 6 拒绝并说明原因）
S ──TCP── LoginOk{uid, token, 成员列表} → 本人；MemberJoin → 其他成员
C ──UDP── Register{uid, token} → S 校验 → 记录地址映射 → RegisterAck
```

**语音转发**（服务器全部工作）：
```
UDP 收到 Voice{uid, seq, opus}（按源地址反查）
  → 刷新 last_seen → 遍历其他成员（有地址的）→ 组包（补来源 uid）→ send_to
```

**离开与清理**：TCP 断开 → 移除成员 + 广播 + 清 UDP 映射；UDP 超时仅清地址

### 6.3 部署（阿里云 ECS 2核2G + 3M）

| 项 | 做法 |
|----|------|
| 产物 | 单个 release 二进制，scp 上传（无运行时依赖） |
| 常驻 | systemd 服务：开机自启 + 崩溃自动拉起 |
| 端口 | TCP + UDP 同一端口号（如 9000），安全组放行两条规则 |
| 资源 | 内存 <10MB，CPU 趋近 0 |
| 日志 | 文件日志：连接/离开/超时清理/异常包计数 |

## 7. 测试与验证策略

### 7.1 分层验证（每层独立可测）

| 层 | 手段 |
|----|------|
| 协议 | 单元测试：编码→解码 roundtrip；畸形数据不 panic |
| 服务器 | 本地跑 + **模拟客户端工具**（CLI 假客户端 × N）：转发正确性/6 人上限/心跳清理/进出广播 |
| 客户端音频 | **本地自听工具**（麦克风→编码→解码→扬声器，不经网络） |
| 端到端（本机） | 模拟客户端 + 真客户端连本地服务器 |
| 端到端（真实） | 局域网双机 → ECS 部署 → 6 人实测 |

### 7.2 验收指标

| 指标 | 目标 |
|------|------|
| 端到端延迟 | 局域网 <150ms；公网同城 <300ms |
| 同时说话 | 2~3 人：混音正常、无爆音 |
| 断线自愈 | 切网/断网 → 15s 内音频与公屏恢复 |
| 资源 | 客户端单核 <15%；服务器 CPU 趋近 0，内存 <10MB |
| 长跑 | 1 小时内存不涨；反复进出无残留 |
| 带宽 | 6 人 <1.5 Mbps |

## 9. 术语

- **抖动缓冲（Jitter Buffer）**：抗网络抖动的排序缓冲，按序列号重排语音帧
- **PLC**：Opus 的丢包隐藏，解码时以空帧触发补音
- **软限幅**：混音求和后平滑削波，防爆音
- **音频可达**：UDP 映射有效（与"在线"＝TCP 连接区分）
