# EchoRoom 计划2 · A 子项目设计：UI 改版 + 个体音量 + 进出音效

**日期**：2026-09-18
**状态**：设计已确认（brainstorming 完成，逐节获批）
**前置**：T12（抖动缓冲）、T13（混音+软限幅）已完成
**上位文档**：`2026-09-18-echoroom-plan2-overview.md`（本文件是其子项目 A 的细化）

## 背景与目标

EchoRoom 原计划（T1–T16）完成单房间语音闭环与基础 UI。计划2 将其提升为向 Oopz 完成度靠拢，共四个子项目（A UI 改版 / B 视频 / C 账号 / D 设置），A 先行。

A 子项目的目标：把成员展示从"纯文字方块"升级为"头像卡片 + 按钮排"，并引入个体音量控制（自己的采集增益、对他人的播放增益）、手动静音与进出音效。

## 范围

**包含**：卡片结构改造（200×230）、按钮排、个体音量、手动静音（采集继续不发包 + 状态广播）、设置持久化、成员区布局重算、进出音效。

**不包含**（明确划出）：
- **观看视图**（点击成员进入观看 / 全屏 / 摄像头小窗）——整体归 B 子项目（无视频流时无法验收）
- **真头像**（上传/存储）——归 C 子项目；C 完成前使用内置占位图
- 自己退出音效（关窗时 webview 销毁，声音播不完）
- 音效音量调节（固定播放音量）

## 1. 卡片结构与视觉

```
┌──────────────────┐
│                  │
│    头像区 200×200   │  ← 内置占位图（C 阶段换真头像）
│                  │
├──────────────────┤
│ 名字    [🔇][🔊][🖥][📷] │  ← 名字条 30px：左名字（溢出省略）、右按钮排
└──────────────────┘
```

- 卡片总尺寸 **200×230**（宽 200 定死；高 = 头像区 200 + 名字条 30）
- 自己的卡按钮排：静音 / 音量 / 投屏 / 摄像头（4 个）；他人的卡：仅音量（1 个）
- 按钮尺寸 24×24，图标用内联 SVG（当前色可随状态变化）
- **激活态样式**：淡色底 + 图标变色——静音 = 淡红底 `rgba(248,113,113,0.15)` + 图标 `#f87171`（现有 --err）；投屏 / 摄像头 = 淡蓝底 `rgba(59,130,246,0.15)` + 图标 `#3b82f6`（现有 --accent）
- **置灰态**：投屏 / 摄像头在 A 阶段功能未实现，**禁用**并置灰，hover 用原生 `title` 提示"即将推出"
- **说话蓝框**：沿用现有逻辑（整卡 2px 主题蓝边框，`speaking` 状态类）
- **他人静音图标**：当某成员处于静音时，其卡片名字条上名字左侧显示红色小静音图标
- **头像占位图**：内置一张默认头像（简单的内联 SVG 人形剪影，作为前端资源），所有成员一致；C 阶段接入真头像后替换

## 2. 交互

- **音量**：点击 24×24 音量按钮 → 卡片旁**弹出小面板**（滑块 + 百分比数值显示），点击面板外任意处关闭；拖动滑块**实时生效**
  - 自己的卡：调节采集增益（自己声音大小），范围 0–200%
    - **拖到 0% = 进入静音**（与静音键同效：不发包 + 广播静音图标 + 按钮变激活态；`self_gain` 写 0）
    - 静音状态下把滑块从 0 拖出（>0）= 解除静音，音量 = 拖到的值
  - 他人的卡：调节播放增益（对这名成员的收听音量），范围 0–200%（拖到 0 仅本地听不到，不触发静音）
- **静音**（自己的卡）：
  - 点击切换开/关；本地立即生效 + 广播状态
  - 进入静音：音量归 0（与“拖到 0%”同一行为）
  - **解除静音：音量回默认 100%**（滑块跳回 100）
  - 不变量：`muted == true` ⟺ `self_gain == 0`（两字段永远同步写，UI 显示无特判）
- **投屏 / 摄像头**：A 阶段点击无效果（禁用态）
- **头像区**：A 阶段无点击行为（B 阶段接观看）

## 3. 数据与状态（Rust 权威）

**真值全部存于 Rust 侧**，前端只做显示与 invoke：

- `self_gain: f32`（0.0–2.0，默认 1.0）——自己的采集增益；静音时恒为 0
- `self_muted: bool`（默认 false）——自己的静音状态；进入静音时 `self_gain` 写 0，解除时写 1.0（静音键）或拖到值（滑块拖出）
- `peer_gains: Map<String, f32>`——**按昵称**记的他人播放增益（uid 每次连接会变，昵称稳定），默认 1.0

**接口**：
- 前端 invoke：`set_self_gain(v)` / `set_muted(b)` / `set_peer_gain(nickname, v)`
- 回显事件：`volume`（携带当前全部音量状态），前端更新 UI
- 初始化：前端启动时通过 `get_config` 拉全量状态

**持久化**：扩展现有 config 文件（`self_gain` / `self_muted` / `peer_gains` 三字段），**改即写**。

**音频链落点**：
- `self_gain`：采集链 **denoise 之后、VAD 之前**乘增益（增益调大 → VAD 更灵敏，符合直觉）；乘后 clamp 到 i16 范围
- `self_muted`：采集线程**照常跑 VAD**（保持状态机连续），但**不发语音包**、**不上报 speaking**；解除静音后自然恢复
- `peer_gain`：混音器新增 `add_scaled(pcm, gain)`；播放线程对每路 sender 按 `uid → 昵称 → gain` 查表后加算
- 混音查表：播放线程每帧查一次（Mutex 低竞争，开销可忽略）

## 4. 协议改动（静音广播）

- 新消息：
  - `Mute`（客户端 → 服务器，含开关值）
  - `Muted`（服务器 → 客户端，{uid, 状态}）——**广播全房间（含发送者本人）**；前端收到后更新卡片图标（自己收到的与本地更新幂等）
- `Members` 同步消息扩展为带 muted 状态（新加入者立即可见谁处于静音）
- 服务器房间态：成员增加 muted 字段
- 自用项目直接改协议字段，无历史兼容包袱

## 5. 布局重算

- 卡片：宽 200 / 高 230
- 成员区高度：230（卡片）+ 12（顶部 padding）+ 8（底部 padding）= **250px**（恰好完整显示一行，第二行藏在可视区外，可滚动）
- 最小窗口 **768×560 保持不变**（左栏 110 + 3×200 卡片 + 间距 ≈ 754，余量 14px）；初始窗口 768×640 不变
- 列数：网格 `auto-fill 200px` 逻辑不变（3～6 列随宽度）

## 6. 进出音效

- **资源**：`in.mp3` / `out.mp3` 复制到 `client/ui/`（前端资源；不放 target/——构建目录会被清理）
- **播放方式**：webview 原生 `Audio` 播放（零新依赖，不走音频管线）
- **触发时机**：
  - 自己**首次**连接成功（应用启动后首次收到 members 同步）→ `in.mp3`
  - 别人进入（`member_join` 事件）→ `in.mp3`
  - 别人退出（`member_leave` 事件）→ `out.mp3`
- **重连不重播**（防网络抖动时连环响）；自己退出不播
- 播放音量固定 `0.5`（不参与音量系统）
- **自动播放策略风险**：webview 可能限制无用户手势的音频播放（他人进出的音效属远端触发）。首次连接成功发生在用户点击"连接"按钮之后（视为已有手势）；若实测仍被阻止，在设置面板的按钮回调里预热 Audio 对象（实施时验证）

## 8. 测试与验收

**Rust 单测**：
- `add_scaled`：增益 0 / 0.5 / 2.0 的样本缩放正确性
- config：新增字段的序列化/反序列化往返
- 协议：`Mute` / `Muted` / `Members`(带 muted) 编解码往返

**手动验收场景**（双客户端）：
1. 拉低他人卡片音量 → 该成员听感变小；拉高 → 变大
2. 静音链路：自己点静音（或把音量拖到 0%）→ 对方卡片出现静音图标、自己的蓝框不亮、对方收不到语音包（send_wav 模式可见发送数不变）；点静音键解除 → 音量回 100%；从 0 拖出 → 解除且音量为拖到值
3. 调自己的音量 → 对方听感变化
4. 重启客户端 → 音量/静音设置保持（按昵称匹配）
5. hover 投屏/摄像头 → 显示"即将推出"，点击无效
6. 进出音效：新客户端加入 → 双方听到 in.mp3；对方退出 → 剩余方听到 out.mp3；重连不响
