# EchoRoom 计划2 总纲

**日期**：2026-09-18
**状态**：需求基线已确认（各子项目细节待逐个 brainstorming 细化）
**前置**：原计划 T12（抖动缓冲）、T13（混音 + 软限幅）完成后启动

## 背景与目标

EchoRoom 原计划（T1–T13）聚焦单房间 6 人语音闭环与基础 UI。
与朋友讨论后，项目目标提升为向 Oopz 的完成度靠拢：投屏、摄像头、账号、设置、UI 改版。

本文件是"计划2"的入口总纲：记录范围、已确认的需求基线、依赖关系与待决策清单。
每个子项目后续各自走 brainstorming → spec → plan → 实现的完整流程。

## A. UI 改版 + 个体音量

### 已确认需求基线

**成员卡片 200×230：**

```
┌──────────────────┐
│                  │
│   头像区 200×200   │  ← 默认显示账号头像
│                  │
├──────────────────┤
│ 名字    [按钮排]   │  ← 名字条 30px：左侧名字，右侧按钮
└──────────────────┘
```

- 自己的卡按钮：静音 / 音量（自己声音大小 = 采集增益）/ 投屏 / 摄像头
- 他人的卡按钮：音量（对该成员的播放增益）

**头像区三种状态：**

1. 无视频流：显示头像图片
2. 该成员有投屏/摄像头流：头像上覆盖"纱"（半透明遮罩）+ 中央半透明按钮（可看提示）
3. 点击进入观看：**成员区整块**变为视频画面（卡片网格暂时隐藏），等比显示（xy 比例锁死）

**观看视图：**

- 右下角全屏按钮；投屏与摄像头同一套交互
- 关闭退出后恢复卡片网格
- 投屏 + 摄像头同开：摄像头为**右下角小窗**（全屏/非全屏均如此），小窗可拖角缩放（比例锁死）、左键拖动移位

### 待决策（A 细化时）

- 音量控件形态（弹出滑块 / 拖拽）
- 静音语义（停止采集 / 采集静音 / 静音不发包——与 T13 门限配合）
- 按钮状态联动（投屏中 / 摄像头中 / 静音中的高亮表现）
- 新卡片尺寸下窗口最小宽度与每行列数重算（旧规范 78×78、150×150 作废）

## B. 视频子系统（投屏 + 摄像头）

### 已确认需求基线

- 采集源两条：屏幕共享、摄像头；共用一条"采集 → 编码 → 传输 → 渲染"管线
- **订阅式按需传输**：点击对方的流才开始接收；同时最多看一路；关闭即停止接收（切换 = 换订阅）
- 服务器延续"只转发"原则：维护订阅关系，只为订阅者转发视频流
- 观看 UI 由 A 子项目承载（观看视图 / 全屏 / 小窗）
- 服务器可升级配置；**需做带宽预算分析**（分辨率 × 帧率 × 码率 × 订阅人数）后给出选型建议

### 待决策（B 细化时）

- 编码方案选型（MJPEG / openh264 / 硬件编码 / 自研），分辨率与帧率档位
- 传输通道（新增 UDP 端口 / 复用现有通道）、丢帧与拥塞策略
- 发送端在自己卡片上的状态表现

## C. 账号系统

### 已确认需求基线

- 登录 / 注册；账号与头像存储于服务器

### 待决策（C 细化时）

- 密码存储方案；会话保持（token）
- 与现有"输入昵称即连接"的兼容策略（是否保留游客模式）
- 头像上传（格式 / 大小上限 / 服务器存储位置）

## D. 设置系统

### 已确认需求基线

- 换头像（依赖 C）、选择输入 / 输出音频设备、主题颜色

### 待决策（D 细化时）

- 设置入口与界面形态
- 音频设备热切换策略（重启采集 / 播放）
- "颜色"的范围（主题色 / 卡片配色）

## 执行顺序

1. **前置收尾**：T12（抖动缓冲）+ T13（混音 + 软限幅）——语音闭环与音量控制地基
2. 逐个推进：**A → B → C → D**（顺序可调；每个子项目走 brainstorming → spec → plan → 实现）

## 服务器与带宽（B 阶段分析预告）

当前设想：2核2G + 3M 带宽起步、可加钱升级。最终选型取决于视频码率档位与最大并发订阅数——B 子项目开始时做一份带宽预算分析再定。
